# 視覚的受け入れチェックリスト

Artifact「Inline Comment Redesign」（https://claude.ai/code/artifact/d19799da-fedc-4687-ad14-24d134bc7e89）の各アートボードから読み取った、実装で外してはいけない箇所の一覧。

**使い方**: 各項目は「この要素について、位置・大きさ・余白がモックアップ通りか」という単位でまとめてある。1つのCSSプロパティ単位（「角丸になっているか」等）ではなく、要素ごとに一つの判断をする。実際に起動した開発サーバー上でPlaywrightによりスクリーンショットを撮影し、同時に各要素の `getBoundingClientRect()` と `getComputedStyle()` を書き出して、各項目を1つずつ対応するアートボードと突き合わせて確認する。判定は3段階: ✅ 一致／⚠️ 近いが要確認／❌ 明らかに異なる。⚠️・❌が1つでもあれば「完了」を報告する前に直す。

**項目番号は変えない。** requirements.md の受け入れ基準4.2・tasks.md のタスク4.1がこの番号を引用している。

**判定結果はこのファイルに残さない。** 判定はそのときのコードに対する1回きりのもので、ここに残すと次の変更で黙って古くなる。判定の記録と実測値は、撮影スイート（`apps/app/playwright/20-basic-features/inline-comment.spec.ts` の視覚照合ブロック）が書き出す `__screenshots__/inline-comment-visual-refresh/` 配下のスクリーンショットと `.json` に置く。**再び判定に使うときは必ず撮り直すこと**——実機フィードバックによる追補（tasks.md タスク5）で、見た目は当初の判定時から大きく変わっている。

**適用対象外の項目について**: `CommentCard`・共有スタイル（`_comment-inheritance.scss`）がすでに決めている値（投稿者アイコンの大きさ、カード左側の吹き出し風の飾り、カードの角の丸み、カードの内側余白、投稿者名と投稿日時の間隔）は、design.md「モックアップ忠実度の適用範囲」の決定により、モックアップと異なっていても意図した仕様である。該当項目には「**（適用対象外）**」と明記した。これらは❌・⚠️にせず、既存の共有スタイルの値のまま表示されていることだけを確認する（モックアップの値に合わせて上書きされていたら、それは範囲外の変更なので逆に指摘する）。**この表はポップオーバーには適用されない**——ポップオーバーは `CommentCard`・共有スタイルを使わず、アバターを独自に30pxにしている。

**モックアップより実装を正とした2点**（design.md「既知の制約」に根拠ごと記載）: ポップオーバーの横幅は340pxではなく576px。保存ボタンの文言は "Save" ではなく "Update"。

## N. ダークモード確認（要件4.4）

項目1〜35はライトモードでの判定である。要件4.4は「ライトモード・ダークモードの両方で、意味付きカラークラスが意図した役割（警告・危険・成功等）を保ったまま表示されること」を求めているため、同じ6状態をダークモードでも撮影し、色の実測値をライトモードと突き合わせる。この節は項目1〜35の番号とは対応しない。

**切り替え方**: `<html>` に `data-bs-theme="dark"` を書く。GROWIが `next-themes` に設定しているのと同じ属性名で、撮影スイート内の他のテストもこの方法を使っている。

**空振りを防ぐ**: ダークモードの撮影は、まずライトモードでページ全体の色を読み、ダークに切り替えてもう一度読んで、**両者が違うことを確かめてから**撮る。そうしないと、テーマがスタイルシートに届かなかった実行が、暗くない6枚を黙って生成して通ってしまう。

**見るところ**: 状態バッジ（警告・成功）、削除確認の警告帯（危険）の3つの意味付きカラークラスについて、文字色と背景色のコントラスト比を両モードで測り、色相（琥珀／緑／赤）が保たれていることを確認する。

**ダークモードで直さないもの**（本スペックの対象外・design.md「既知の制約」参照）:

- 編集モードの入力欄（CodeMirror）の背景が白いまま。インラインコメント固有ではなく、GROWIのコメント入力欄全体の挙動である（通常のページコメントでも同じ）。文字は白地に濃い文字で読める
