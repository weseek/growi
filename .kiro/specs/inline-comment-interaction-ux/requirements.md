# Requirements Document

## Project Description (Input)

`inline-comment`（`.kiro/specs/inline-comment/`）の実装を実際に使ってみたユーザーから、以下4点の指摘があった。本スペックはこれらを amend spec として扱い、実装完了後に内容を対象スペックへ戻して自身を削除する。

1. 本文中で、次の3つの状況が見た目上区別できない。
   - 単なる（インラインコメントと無関係な）テキスト選択
   - 新規インラインコメントを作成しようとして選択中／入力中の範囲
   - 既にインラインコメントが付いている保存済みの範囲（さらに、その上に新しい選択が重なったときにどちらを見ているか分からない）
2. 本文中のインラインコメント対象範囲を hover／click／（タブレット以下のサイズでは）tap すると、その場でコメント内容を確認できるようにしたい。その場での返信（reply）もできるようにしたいが、UIは簡易なもので構わない。インラインコメント自体の編集は引き続き対象外。
3. 画面最下部のコメント一覧中のインラインコメント項目をクリックすると、本文中の対応するハイライト箇所へスクロールするようにしたい。
4. 画面最下部のコメント一覧中の、インラインコメントに対する返信UIが、通常コメントの返信UIと異なる。インラインコメント側も通常コメントと同じ返信UIにしたい：「Reply...」ボタンを押すとメンション対応の入力コンポーネントが現れ、Cancelを押すと「Reply...」ボタンに戻る仕様。現状の簡素な入力欄を置き換える。

## Amend target

- **対象スペック（複数）**:
  - `.kiro/specs/inline-comment/` — 最終的な戻し先。Requirement 1〜4（本ドキュメント）を新規 Requirement として追加する
  - `.kiro/specs/inline-comment-visual-consistency/` — まだ対象スペックへの fold-back（`.claude/rules/spec-lifecycle.md` が定める、変更を戻して自身を削除する手順）が完了していないため、本スペックが直接その `requirements.md` の **Requirement 12.8 を上書き**する（「作成中の範囲を示すハイライトと、保存済みコメントの対象範囲を示すハイライトに、同じ色を使う」という決定を撤回し、両者を異なる色にする）。ユーザー判断により確定済み。fold-back の順序は実装時点で調整してよいが、最終的に矛盾する記述が両スペックに残らないようにすること。
- **Revalidation Triggers への影響**: `inline-comment-visual-consistency` の「テーマ由来のハイライト色トークン」の仕組み（`--grw-inline-comment-marker-bg` 等）を土台にするため、そちらのトークン設計が変わった場合は本スペックの色分けも再確認が必要。

## Boundary Context

- **In scope**:
  - 作成中（選択中・入力中）の範囲のハイライト色と、保存済みコメントの対象範囲のハイライト色を区別すること
  - 保存済みハイライトと、それに重なる選択中ハイライトの両方を、利用者が見分けられる形で同時に表示すること
  - 本文中の保存済みインラインコメント範囲を hover／click／tap した際に、その場で内容を確認し簡易な返信ができるポップオーバー等の手段を提供すること
  - 画面最下部のコメント一覧のインラインコメント項目から、本文中の対応するハイライト範囲へのスクロールナビゲーション
  - 画面最下部のコメント一覧における、インラインコメントへの返信UIを通常コメントの返信UIと統一すること
- **Out of scope**:
  - インラインコメント本体（起点・返信とも）の編集・削除（引き続き対象外）
  - アンカーの計算・照合・再アンカーの仕組みそのもの（既存のまま。再アンカーに失敗した場合の扱いは本スペックの対象内だが、再アンカー自体の改善は対象外）
  - 選択→起点→フォームという作成フローの2段階の流れそのもの
  - 通常コメント側の振る舞い・見た目の変更
- **Adjacent expectations**:
  - `InlineCommentHighlight` / `PendingSelectionHighlight`（`inline-comment-visual-consistency` で実装済み）が提供する、テーマ由来の CSS カスタムプロパティ経由のハイライトの仕組みを土台にする
  - `CommentCard` 経由で表示される一覧項目・返信の構造（`inline-comment-visual-consistency` で実装済み）を土台にする
  - 通常コメントの返信・入力体験（メンション対応の入力コンポーネント）を土台にする

## Requirements

### Requirement 1: ハイライトの種別ごとの視覚的な区別

**Objective:** As a ページ閲覧者, I want 作成中の範囲と既存のインラインコメントの範囲を見た目で区別できるようにしてほしい, so that いま見ているハイライトが何を意味しているのか誤解しない

#### Acceptance Criteria

1. The インラインコメント機能 shall 作成中（選択中・入力中）の範囲を示すハイライトの色と、保存済みコメントの対象範囲を示すハイライトの色を、異なる色にする
2. While 利用者が保存済みコメントの対象範囲と重なる位置でテキストを選択している, the インラインコメント機能 shall 保存済みコメントのハイライトと、選択中の範囲のハイライトの両方を、利用者が見分けられる形で表示する
3. The インラインコメント機能 shall 作成中のハイライト色・保存済みのハイライト色を、それぞれ独立にテーマから上書きできるようにする
4. Where テーマがどちらのハイライト色もカスタマイズしていない, the インラインコメント機能 shall 両方の既定色に、互いに見分けやすい色を使う
5. The インラインコメント機能 shall テキスト選択中・入力フォームが開いている間・保存後、という3つの時点それぞれで、対応するハイライト色を一貫して表示し続ける（テーマ追随・色の出どころの一本化・入力欄へのフォーカス移動時に消えないこと等、既存の Requirement 12.1〜12.7 の性質は維持する）

### Requirement 2: 本文中のハイライトからのその場での内容確認・簡易返信

**Objective:** As a ページ閲覧者, I want 本文中のインラインコメント範囲を hover／click／tap すると、その場で内容を確認し簡単に返信できるようにしてほしい, so that 画面最下部の一覧まで探しに行かなくても文脈を保ったまま確認・返信できる

#### Acceptance Criteria

1. When 利用者がデスクトップサイズの画面で、保存済みインラインコメントのハイライト範囲にマウスカーソルを重ねた、またはその範囲をクリックした, the インラインコメント機能 shall その場にコメントの内容（投稿者・投稿日時・本文・既存の返信）を表示する手段を提供する
2. When 利用者がタブレット以下のサイズの画面で、保存済みインラインコメントのハイライト範囲をタップした, the インラインコメント機能 shall 同じ内容確認手段を提供する
3. The インラインコメント機能 shall その場での内容確認手段の中に、返信を投稿できる簡易な入力欄を含める（画面最下部の一覧の返信UIと同一の作りである必要はない）
4. When 利用者がその場での内容確認手段の外側をクリックした、または閉じる操作をした, the インラインコメント機能 shall その表示を閉じる
5. The インラインコメント機能 shall その場での内容確認手段から、インラインコメント本文自体の編集を提供しない
6. If 対応するインラインコメントの対象範囲が再アンカリングに失敗しており本文中にハイライトが表示されていない, then the インラインコメント機能 shall その場での内容確認手段を提供しない

### Requirement 3: 一覧からハイライトへのスクロールナビゲーション

**Objective:** As a ページ閲覧者, I want 画面最下部のコメント一覧にあるインラインコメント項目をクリックすると本文中の該当箇所へ移動してほしい, so that 一覧と本文を行き来して文脈を探さなくてよい

#### Acceptance Criteria

1. When 利用者が画面最下部のコメント一覧内のインラインコメント項目をクリックした, the インラインコメント機能 shall 本文中の対応するハイライト範囲が見える位置まで自動的にスクロールする
2. If 対応するインラインコメントの対象範囲が再アンカリングに失敗しており本文中にハイライトが表示されていない, then the インラインコメント機能 shall スクロールを行わず、対応する範囲が見つからないことを利用者に分かる形で示す
3. When 本文中の対応するハイライト範囲までスクロールした, the インラインコメント機能 shall 利用者がどの範囲に移動したか分かるように、その範囲を一時的に強調する

### Requirement 4: 一覧内の返信UIの通常コメントとの統一

**Objective:** As a ページ閲覧者, I want 画面最下部のコメント一覧でインラインコメントに返信するときのUIが通常コメントへの返信と同じであってほしい, so that コメントの種類によらず同じ操作方法で返信できる

#### Acceptance Criteria

1. The インラインコメント機能 shall 画面最下部のコメント一覧内で、インラインコメントへの返信の起点として、通常コメントの返信と同じ文言・見た目の「Reply...」ボタンを表示する
2. When 利用者が「Reply...」ボタンをクリックした, the インラインコメント機能 shall 通常コメントの返信と同じ、メンション対応の入力コンポーネントを表示する
3. When 利用者が返信入力欄でCancel操作を行った, the インラインコメント機能 shall 入力コンポーネントを閉じ、表示を「Reply...」ボタンに戻す
4. The インラインコメント機能 shall 現状の簡素な入力欄による返信UIを、本要件の統一されたUIに置き換える
5. The インラインコメント機能 shall 統一後も、返信の投稿・一覧への反映という既存の振る舞いを変えない
