# Requirements Document

## Project Description (Input)

すでに実装済みのインラインコメント機能（`.kiro/specs/inline-comment/`、選択→作成の2段階フローを含む）について、実装した画面をモックアップと突き合わせたところ、見た目の差が大きいことが分かった。差の中身は次の3つに分かれる。

1. 作成の起点ボタン・キャンセル・投稿の各ボタンに CSS クラスが1つも付いておらず、ブラウザ標準のボタンがそのまま出ている。GROWI 本体は Bootstrap 5 を使い、さらに 16 種類のテーマを切り替えられる仕組み（`packages/preset-themes/`）を持っているので、それに乗った見た目にしなければならない。
2. 本文中のハイライト色が、テーマを切り替えても変わらない固定色になっている。またテキストを選択している最中はブラウザ標準の青、入力フォームを開いて入力欄にカーソルを移すと何も表示されない、コメント保存後は薄いベージュ、と3つの状態でばらばらの見え方になっている。モックアップではこの3状態がすべて同じ黄色系のマーカー色で塗られている。テーマごとに色を変えられるようにし、既定では検索キーワードのマーカー色に合わせる。
3. インラインコメントの一覧が、通常のページ末尾コメントとは別の場所に、別の見た目で並んでいる。投稿者のアイコン・名前・投稿日時も出ていない。モックアップでは両者が1つの一覧の中に、同じ見た目の箱で並んでいる。

本スペックは `inline-comment` に対する amend spec であり、実装完了後に内容を `.kiro/specs/inline-comment/` へ戻して自身を削除する。

## Introduction

インラインコメント機能の表示部分を、GROWI 本体の見た目の仕組み（Bootstrap 5 のクラスと CSS カスタムプロパティ、および preset-themes によるテーマ切り替え）に合わせ直す。あわせて、インラインコメントを通常のコメントと同じ一覧の中に、同じ見た目の箱で並べる。アンカーの計算方法、保存するデータの中身、選択→作成の2段階の操作の流れは変更しない。

## Amend target

- **対象スペック**: `.kiro/specs/inline-comment/`
- **変更する契約**:
  - `requirements.md` に Requirement 11 / 12 / 13 を追加する（既存の 1〜10 は番号も本文も変えない）
  - `design.md` の Components and Interfaces（`SelectionActionButton` / `InlineCommentForm` / `InlineCommentHighlight` / `InlineCommentList`）と File Structure Plan を書き換える
  - `design.md` の Data Contracts に、一覧取得の応答へ投稿者情報を含める変更を反映する
- **Revalidation Triggers への影響**: `inline-comment` の design.md が持つ「共有リンク閲覧者にインラインコメントを渡さない」条件に、新しく「`Comments` / `PageComment` は共有リンク画面でも使われるため、インラインコメントは `PageView` から props で渡し、`PageComment` 自身では取得しない」という条件を追加する。

## Boundary Context

- **In scope**:
  - 作成の起点ボタン・入力フォーム・引用表示・操作ボタン群の見た目を、Bootstrap 5 のクラスとテーマ由来の CSS カスタムプロパティで組み直す
  - 本文中のハイライト色を、テーマごとに変えられる CSS カスタムプロパティに置き換える
  - テキスト選択中・入力フォームを開いている間・コメント保存後、の3つの状態でハイライトの見え方をそろえる
  - インラインコメントの一覧項目を、通常コメントと同じ箱（投稿者アイコン・名前・投稿日時を含む）で表示する
  - インラインコメントを通常コメントと同じ一覧の中に、投稿日時順で混ぜて並べる
  - 一覧取得の応答に投稿者情報を含める（`serializeUserSecurely` を通す）
  - インラインコメント側にだけある要素（未解決／解決済みの表示、解決トグル、引用文）を、同じ箱の中の差分として置く
  - 現在ベタ書きされている英語ラベル（Resolved / Unresolved / Resolve / Reopen / Reply / Cancel / Comment）を i18n のキーに置き換える
- **Out of scope**:
  - アンカーの計算方法、あいまい一致の照合、再アンカーの挙動（Requirement 1〜5 の振る舞い）
  - 保存するデータのうち、投稿者を表示するために必要な範囲を超える変更
  - 選択→起点ボタン→入力フォーム、という2段階の操作の流れそのもの（Requirement 7〜10 の振る舞い）
  - インラインコメントの編集・削除、共有リンク閲覧者への公開（引き続き対象外）
  - 通常コメント側の投稿・編集・削除・通知の振る舞い
  - `CodeMirrorEditorComment` そのものの作り替え（design.md の Open Question として残す）
  - 未解決・解決済みの札の配色（現在の `bg-warning text-dark` のまま。`warning` 系がテーマごとに再生成されないことは分かっているが、札の色を変える受け入れ条件を立てていないので触らない）
- **Adjacent expectations**:
  - 通常コメントの箱の見た目は `apps/app/src/client/components/PageComment/_comment-inheritance.scss` の共有定義（`%bg-comment` / `%comment-section` / `%user-picture`）がすでに1か所で持っている。インラインコメント側は同じ定義を使い、クラス名を写し取る形にはしない。
  - 検索キーワードのマーカー色は `--grw-marker-bg`（テーマごとに上書きされる）で、既定値は `--grw-marker-bg-yellow` = `#FFFA90`。インラインコメントのハイライトはこの色を既定として引き継ぐ。
  - `Comments` は共有リンク画面（`ShareLinkPageView`）からも使われる。インラインコメントの取得を `Comments` / `PageComment` の中に置くと共有リンク閲覧者に届いてしまうため、取得は呼び出し側で行い、値として渡す。

## Requirements

### Requirement 11: テーマに追随する作成 UI の表示

**Objective:** As a GROWI 管理者, I want インラインコメントの作成 UI が選んだテーマの配色に従ってほしい, so that ページの他の部分と見た目がそろい、テーマを変えたときに一部だけ浮いてしまうことがない

#### Acceptance Criteria

1. The インラインコメント機能 shall 作成の起点・入力フォーム・その操作ボタン群のすべての表示要素に、Bootstrap 5 のクラスまたはテーマが提供する CSS カスタムプロパティ経由で背景色・境界線色・文字色を与える
2. The インラインコメント機能 shall 作成の起点・入力フォーム・その操作ボタン群の色指定に、色の直値（16進表記・`rgb()`・`rgba()`・色名）を使わない
3. When 管理者が GROWI のテーマを別のテーマに切り替えた, the インラインコメント機能 shall 作成の起点・入力フォーム・操作ボタン群の背景色・境界線色・文字色を、切り替え後のテーマの値に変える
4. When 表示中の配色が明るい配色から暗い配色に切り替わった, the インラインコメント機能 shall 作成の起点・入力フォーム・操作ボタン群の背景色・境界線色・文字色を、暗い配色側の値に変える
5. The インラインコメント機能 shall 送信ボタンをページ内の主操作ボタンと同じ見た目で、取り消しボタンを副次操作ボタンと同じ見た目で表示する
6. The インラインコメント機能 shall 作成の起点・入力フォーム・一覧項目に表示するすべての文言を、翻訳ファイルのキー経由で表示する

### Requirement 12: テーマごとに変えられるハイライト色

**Objective:** As a GROWI 管理者, I want インラインコメントの対象範囲を示すハイライト色をテーマごとに変えられるようにしてほしい, so that テーマの配色の中でハイライトが読みづらくなったり浮いたりしない

#### Acceptance Criteria

1. The インラインコメント機能 shall 本文中のハイライト色を、テーマ側から上書きできる 1 つの CSS カスタムプロパティから読む
2. Where テーマがそのカスタムプロパティを上書きしていない, the インラインコメント機能 shall 検索キーワードのマーカー色と同じ色をハイライト色として使う
3. When 管理者がハイライト色を上書きしているテーマに切り替えた, the インラインコメント機能 shall 本文中のハイライトの色を、そのテーマが指定した色に変える
4. While 利用者が本文中のテキストを選択していて、まだ作成の起点を選んでいない, the インラインコメント機能 shall 選択されている範囲を第1項のハイライト色で表示する
5. While 入力フォームが開いている, the インラインコメント機能 shall 対象の範囲を第1項のハイライト色で表示し続ける
6. When 利用者が入力欄にカーソルを移してブラウザ上の選択が解除された, the インラインコメント機能 shall 対象の範囲のハイライト表示を消さない
7. When 入力フォームが送信または取り消しで閉じた, the インラインコメント機能 shall 作成中の範囲を示していたハイライトを消す
8. The インラインコメント機能 shall 作成中の範囲を示すハイライトと、保存済みコメントの対象範囲を示すハイライトに、同じ色を使う

### Requirement 13: 通常コメントとインラインコメントの見た目の統一

**Objective:** As a ページ閲覧者, I want インラインコメントと通常コメントが1つの一覧に同じ見た目で並んでほしい, so that ページに付いたコメントを1か所で、種類を意識せずに読める

#### Acceptance Criteria

1. The インラインコメント機能 shall インラインコメントを、通常コメントの一覧と同じ 1 つの一覧の中に表示する
2. The インラインコメント機能 shall 一覧の中で、インラインコメントと通常コメントを投稿日時の順に並べる
3. The インラインコメント機能 shall インラインコメントの一覧項目に、通常コメントと同じ背景色・境界線・角丸・余白の箱を使う
4. The インラインコメント機能 shall インラインコメントの一覧項目に、投稿者のアイコン・投稿者名・投稿日時を、通常コメントと同じ並び・同じ大きさで表示する
5. When 利用者がインラインコメントを含むページの一覧を取得した, the インラインコメント機能 shall 各インラインコメントの投稿者情報を、通常コメントの一覧取得と同じ秘匿処理を通した形で応答に含める
6. The インラインコメント機能 shall インラインコメントの一覧項目に、対象範囲の引用文を本文より前に表示する
7. The インラインコメント機能 shall インラインコメントの一覧項目に、未解決・解決済みの表示と解決トグルを、通常コメントと共通の箱の中に置く
8. If 共有リンク経由でページが表示された, then インラインコメント機能 shall 一覧にインラインコメントを一切含めない（Requirement 6 の非公開化の方針を引き継ぐ）
9. The インラインコメント機能 shall 通常コメントの一覧項目の見た目を変えない
10. The インラインコメント機能 shall インラインコメントの一覧項目に、通常コメントとの種別を区別できる見出し行を、共通の箱の中に表示する
